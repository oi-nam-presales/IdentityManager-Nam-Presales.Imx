# Plan: Create a Generic Identity Manager Web Portal Plugin (v10)

## Overview

This is a proven, step-by-step guide for creating a custom Angular library plugin for the One Identity Manager Web Portal (v10, Angular 20, NX 22). Based on the successfully implemented `frozen-jobs-plugin`, this guide generalizes the approach into a reusable blueprint called `utilities-plugin`.

The plugin architecture follows this pattern:
- **Dashboard tile** (badge with count) → registered via `ExtService.register('Dashboard-SmallTiles', ...)`
- **Authorization check** via `/portal/person/{uid}/rolememberships/AERole` endpoint (portal-scoped, no opsupport session needed)
- **Custom API backend** via a `.tgz` package providing a `V2Client` for your custom C# API server plugin
- **Sidesheet** for detail view → opened on tile click
- **Dialog** for individual item detail → opened on table row click
- **Auto-refresh timer** to keep the badge count current

---

## Prerequisites

| Item | Purpose |
|------|---------|
| Custom `.tgz` API client package (e.g. `imx-api-utilsplugin.tgz`) | TypeScript types + V2Client for your custom endpoints |
| Custom C# server DLL (e.g. `UtilsPlugin.CompositionApi.Server.Plugin.dll`) | Deployed to API server; provides REST endpoints |
| The `imxweb` workspace with all dependencies installed | Development environment |


### 2.4 Portal dynamic import service

In `projects/qer-app-portal/src/app/dynamic-import/portal-dynamic-modules-import.service.ts`:

1. Add import at top:
```typescript
import { UtilitiesPluginModule } from "utilities-plugin";
```

2. Add case in `loadFirstPartyModules` switch:
```typescript
case 'utilities-plugin':
  callback = async () => {
    await import('utilities-plugin');
    return [UtilitiesPluginModule];
  };
  break;
```

> **IMPORTANT**: Do NOT also add it to `loadThirdPartyModules` — this causes double-loading and duplicate tiles.
> Use EITHER first-party (server-registered via `imx-plugin-config.json`) OR third-party (hardcoded), never both.

## Phase 3: Core Services

### 3.1 Custom API Service (`utils-plugin-api.service.ts`)

```typescript
import { Injectable } from '@angular/core';
import { V2Client } from '@imx-modules/imx-api-utilsplugin';
import { AppConfigService, ClassloggerService } from 'qbm';

@Injectable({ providedIn: 'root' })
export class UtilsPluginApiService {
  private c: V2Client;
  public get client(): V2Client { return this.c; }

  constructor(
    private readonly config: AppConfigService,
    private readonly logger: ClassloggerService,
  ) {
    try {
      this.logger.debug(this, 'Initializing UtilsPlugin API service');
      const schemaProvider = config.client;
      this.c = new V2Client(this.config.apiClient, schemaProvider);
    } catch (e) {
      this.logger.error(this, e);
    }
  }
}
```
> **Pattern**: `V2Client` needs `apiClient` (for HTTP) and `schemaProvider` (for entity schema). Both come from `AppConfigService`.

## Phase 4: Authorization Check (AERole via Portal API)

**DO NOT use** `/opsupport/` endpoints — require opsupport session scope, unavailable in portal context.

**DO NOT use** the `search` parameter on the AERole endpoint — causes server 500 errors.

**Correct approach** — page through `/portal/person/{uid}/rolememberships/AERole` with `withProperties: '-RoleFullPath'`:

```typescript
private async hasRequiredRole(uidPerson: string): Promise<boolean> {
  const pageSize = 100;
  let startIndex = 0;

  do {
    const result = await this.qerApiService.client.portal_person_rolememberships_AERole_get(uidPerson, {
      withProperties: '-RoleFullPath',
      PageSize: pageSize,
      StartIndex: startIndex,
    });

    const entities = result.Entities ?? [];

    if (entities.some((e) => e.Columns?.['RoleFullPath']?.Value === 'Base roles\\Operations support')) {
      return true;
    }

    startIndex += entities.length;
    if (entities.length === 0 || startIndex >= result.TotalCount) {
      break;
    }
  } while (true);

  return false;
}
```

**Key details:**
- `withProperties: '-RoleFullPath'` — the `-` prefix means "include RoleFullPath alongside default columns"
- Response type: `EntityCollectionData` with `TotalCount: number` (uppercase) and `Entities: EntityData[]`
- `EntityData.Columns['RoleFullPath'].Value` contains the full path string
- Value format: `'Base roles\\Operations support'` (backslash-separated path)
- `imx_SessionService.SessionState?.UserUid` provides current user's UID
- Short-circuits on first match for performance
- `QerApiService` is from `qer`, `imx_SessionService` is from `qbm`

## Phase 5: Dashboard Tile Component

**TypeScript:**
```typescript
import { Component, OnDestroy, OnInit } from '@angular/core';
import { EuiSidesheetService } from '@elemental-ui/core';
import { MyItem } from '@imx-modules/imx-api-utilsplugin';
import { imx_SessionService } from 'qbm';
import { QerApiService } from 'qer';
import { MyFeatureSidesheetComponent } from '../my-feature-sidesheet/my-feature-sidesheet.component';
import { UtilsPluginApiService } from '../utils-plugin-api.service';

@Component({
  selector: 'imx-my-feature-tile',
  templateUrl: './my-feature-tile.component.html',
  standalone: false,
})
export class MyFeatureTileComponent implements OnInit, OnDestroy {
  public count = 0;
  public isAuthorized = false;
  public loading = true;

  private items: MyItem[] = [];
  private refreshTimer: ReturnType<typeof setInterval> | null = null;
  private static readonly REFRESH_INTERVAL_MS = 60_000;

  constructor(
    private readonly session: imx_SessionService,
    private readonly qerApiService: QerApiService,
    private readonly utilsPluginApi: UtilsPluginApiService,
    private readonly sidesheet: EuiSidesheetService,
  ) {}

  public async ngOnInit(): Promise<void> {
    try {
      const uidPerson = this.session.SessionState?.UserUid;
      if (uidPerson) {
        this.isAuthorized = await this.hasRequiredRole(uidPerson);
      }
      if (this.isAuthorized) {
        this.items = await this.utilsPluginApi.client.my_endpoint_get();
        this.count = this.items.length;
        this.startRefreshTimer();
      }
    } catch (error) {
      console.error('[MyFeatureTile] Error during initialization:', error);
    } finally {
      this.loading = false;
    }
  }

  public ngOnDestroy(): void {
    if (this.refreshTimer !== null) {
      clearInterval(this.refreshTimer);
    }
  }

  public onTileClick(): void {
    this.sidesheet.open(MyFeatureSidesheetComponent, {
      title: 'My Feature',
      padding: '0px',
      width: '800px',
      testId: 'my-feature-sidesheet',
      data: { items: this.items },
    });
  }

  private startRefreshTimer(): void {
    this.refreshTimer = setInterval(() => {
      void this.refreshData();
    }, MyFeatureTileComponent.REFRESH_INTERVAL_MS);
  }

  private async refreshData(): Promise<void> {
    try {
      this.items = await this.utilsPluginApi.client.my_endpoint_get();
      this.count = this.items.length;
    } catch (error) {
      console.error('[MyFeatureTile] Refresh error:', error);
    }
  }

  // See Phase 4 for hasRequiredRole() implementation
}
```

**Template (`my-feature-tile.component.html`):**
```html
@if (isAuthorized && !loading) {
  <imx-badge-tile
    data-imx-identifier="start-tile-my-feature"
    [caption]="'My Feature'"
    [tooltip]="'Description of what this tile shows.'"
    [value]="count.toString()"
    [identifier]="'my-feature'"
    (actionClick)="onTileClick()">
  </imx-badge-tile>
}
```

**Critical notes:**
- `catch` block is MANDATORY — without it, API errors bubble to Angular's global error handler, showing "An unexpected server error occurred" dialog to the user
- `@if (isAuthorized && !loading)` hides the tile completely for unauthorized users
- `standalone: false` is required in this workspace
- Timer only starts AFTER initial authorization + data fetch succeeds
- `ngOnDestroy` clears timer to prevent memory leaks when navigating away

1. **Console tab** → look for `🔥 utilities-plugin loaded` (confirms module initialized)
2. Login as user WITH the required AERole → tile appears on dashboard with correct count
3. Login as user WITHOUT the role → tile does not appear (hidden by `@if (isAuthorized && !loading)`)

5. Click a table row → detail dialog opens; scrolls for long error messages
6. Wait 60 seconds → badge count refreshes automatically
7. **Network tab** → no red (failed) requests; no 4xx/5xx responses

## Deployment to IIS

### Artifacts to deploy

| Artifact | IIS Location | Purpose |
|----------|-------------|---------|
| Full contents of `dist/qer-app-portal/` | Portal web root (replace existing) | Portal + plugin lazy chunk bundled inside |
| `Html_utilities-plugin/imx-plugin-config.json` | Plugin folder alongside portal root | Registers plugin: API server reads this at startup and includes `utilities-plugin` in the `PlugInInfo[]` sent to every portal client |
| `UtilsPlugin.CompositionApi.Server.Plugin.dll` | API server plugins/bin folder | Provides custom REST endpoints (e.g. `/portal/imutils/...`) |

### NOT deployed

| Artifact | Why not |
|----------|---------|
| `imx-api-utilsplugin.tgz` | Build-time only — TypeScript types are compiled into the portal JS chunks |
| `dist/utilities-plugin/` folder | Already bundled inside the portal build output |
| `node_modules/` | Development environment only |

### How `imx-plugin-config.json` works

The Identity Manager API server scans all `Html_*/imx-plugin-config.json` files on startup. Each file registers plugins to be loaded for specific portals. When the portal calls the session endpoint, the server includes `{ Container: 'utilities-plugin', Name: 'UtilitiesPluginModule' }` in its `PlugInInfo[]` response. The portal's `loadFirstPartyModules` switch handles this and performs the dynamic `import('utilities-plugin')`.

## Lessons Learned (Pitfalls to Avoid)

| Problem | Root Cause | Fix |
|---------|-----------|-----|
| `search` parameter on AERole endpoint causes server 500 | Server-side full-text search not configured for this endpoint | Do not use `search`. Page through all results and check `RoleFullPath` column value client-side |
| `/opsupport/` endpoints fail from portal | These require opsupport session scope, unavailable in `/portal/` context | Use only `/portal/` scoped endpoints for authorization checks |
| `npx nx serve qer-app-portal` fails with `browserTarget` schema error | NX 22 schema validation rejects `browserTarget` in `project.json` | Use `ng serve qer-app-portal --configuration development` instead |
| NG0912 Component ID collision | Two components with identical metadata hash to the same ID | Add unique `host: { 'data-component-id': 'my-unique-name' }` to component decorator |
| Badge tile appears twice on dashboard | Module loaded via BOTH `loadFirstPartyModules` AND `loadThirdPartyModules` | Use only ONE loading mechanism — never both |
